## �� Overview

Prompt engineering is the skill of communicating with LLMs effectively. A well-engineered prompt can be the difference between a generic, useless response and a precise, expert-level answer. For data science workflows, good prompts can automate data cleaning, generate analysis code, explain model outputs, and write documentation.

## 💡 គំនិតសំខាន់

Think of the LLM as an extremely knowledgeable consultant who has read everything ever written. Prompting is how you brief them on what you need. A vague brief gets a vague result. A specific, context-rich brief gets an expert answer tailored to your exact situation.

## 📖 ការសិក្សាស៊ីជម្រៅ

### The Anatomy of a Good Prompt

A strong prompt typically has four components:

1. **Role** — tell the model who it is
2. **Context** — provide relevant background
3. **Task** — state exactly what you need
4. **Constraints** — specify format, length, tone, what to avoid

### Prompting Techniques

| Technique | When to use | Example |
|---|---|---|
| **Zero-shot** | Simple, well-defined tasks | "Translate this to French:" |
| **Few-shot** | Complex tasks needing format guidance | Provide 2-5 examples first |
| **Chain-of-thought** | Multi-step reasoning, maths | "Think step by step:" |
| **Role prompting** | Domain expertise needed | "You are a senior data scientist..." |
| **Self-consistency** | High-stakes answers | Generate 5 answers, pick the majority |
| **RAG** | Need current/specific facts | Inject retrieved documents into context |

def fill_template(template: str, **kwargs) -> str:
    """Fill a prompt template with values."""
    return template.format(**kwargs)

## ✅ ចំណុចសំខាន់ៗដែលត្រូវចាំ

Effective prompt engineering follows a consistent structure: **role + context + task + constraints**. Use **few-shot examples** to show the model the exact format you want. **Chain-of-thought** dramatically improves accuracy on reasoning, maths, and code tasks by externalising the reasoning process. Build **reusable templates** for recurring tasks — code review, EDA analysis, error explanation — to get consistent, high-quality results without re-engineering prompts each time. For high-stakes outputs, use **self-consistency**: generate multiple responses and take the majority answer.

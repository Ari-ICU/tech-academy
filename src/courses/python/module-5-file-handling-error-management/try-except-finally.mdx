## 🌐 សេចក្តីផ្តើម (Overview)

តើអ្នកធ្លាប់ប្រើកម្មវិធីទូរស័ព្ទណាមួយហើយស្រាប់តែវាបិទខ្លួនឯងភ្លាមៗទេ? នោះមកពីអ្នកសរសេរកម្មវិធីមិនបានរៀបចំកូដដើម្បី "ចាប់" កំហុសដែលមិនបានព្រាងទុក។ 
នៅក្នុង Python នៅពេលមានអ្វីមួយខុសប្រក្រតី (ឧទាហរណ៍ ចែកលេខនឹងសូន្យ ឬរកឯកសារមិនឃើញ) Python នឹងបោះចោល **Exception** ហើយបើគ្មានអ្នកណាចាប់វាទេ កម្មវិធីនឹងគាំង (Crash) ភ្លាម។ មេរៀននេះនឹងបង្រៀនអ្នកពីសិល្បៈក្នុងការ "ចាប់" កំហុស ដើម្បិឱ្យកម្មវិធីរបស់អ្នកដំណើរការបានរលូនទោះក្នុងកាលៈទេសៈណាក៏ដោយ។

---

## 📚 រៀនពាក្យបច្ចេកទេស (Definitions)

- **Syntax Error:** កំហុសវេយ្យាករណ៍ (សរសេរកូដខុសច្បាប់ Python) ដែលធ្វើឱ្យកម្មវិធីមិនអាចចាប់ផ្តើមបានតាំងពីដំបូង។
- **Exception (Runtime Error):** កំហុសដែលកើតឡើងពេលកម្មវិធីកំពុងដើរ (ឧ. ព្យាយាមបើកឯកសារដែលមិនមាន ឬអ្នកប្រើប្រាស់បញ្ចូលទិន្នន័យខុស)។
- **Try Block:** កន្លែងដែលអ្នកដាក់កូដដែលអាចមានហានិភ័យក្នុងការគាំង។
- **Except Block:** កន្លែងដែលអ្នកប្រាប់ Python ថាត្រូវធ្វើអ្វីបន្ត ពេលកំហុសកើតឡើង។

---

## 🧠 រចនាសម្ព័ន្ធរបស់កំហុស (Python Exception Hierarchy)

Python Exceptions មិនមែនកើតឡើងផ្តេសផ្តាសទេ! វាមានរចនាសម្ព័ន្ធជាមែកធាង (Hierarchy) ច្បាស់លាស់៖

```text
BaseException
├── SystemExit
├── KeyboardInterrupt
├── GeneratorExit
└── Exception
    ├── ValueError
    ├── TypeError
    ├── FileNotFoundError
    ├── ZeroDivisionError
    ├── KeyError
    ├── IndexError
    └── ...
```

នៅពេលដែលយើងចង់បង្កើត Custom Exception (កំហុសផ្ទាល់ខ្លួន) យើងគួរតែ Inherit ពី `Exception` មិនមែន `BaseException` នោះទេ!

## 💡 គំនិតគោល (The Core Idea)

### ការចាប់យកកំហុសក្នុងអថេរ (Introduce Exception as `e`)

វិធីដ៏ល្អបំផុតក្នុងការចាប់យកកំហុស គឺរក្សាទុកវាចូលទៅក្នុងអថេរ `e` ដើម្បីឱ្យយើងអាចដឹងថាមានរឿងអ្វីកើតឡើង។

```python
try:
    age = int(input("សូមបញ្ចូលអាយុ៖ "))
except ValueError as e:
    print(f"មានកំហុស៖ {e}")
```
> **ចំណាំ៖** `e` គឺជា Object ដែលផ្ទុកព័ត៌មានលម្អិតអំពី Exception នោះ។ វាងាយស្រួលអានជាងការគ្រាន់តែចាប់យក `except ValueError:` ទទេៗ។

## 📖 ការសិក្សាស៊ីជម្រៅ (In Depth)

### ១. គ្រោះថ្នាក់នៃការប្រើ Bare Except

ការសរសេរ `except:` ដោយមិនប្រាប់ឈ្មោះកំហុស គឺជារឿងដ៏គ្រោះថ្នាក់បំផុត។ 

```python
try:
    while True:
        pass
except:
    print("កម្មវិធីមិនអាចបញ្ឈប់បានទេ!")
```
**តើមានអ្វីកើតឡើង?** ពេលអ្នកចុច `Ctrl + C` ដើម្បីបញ្ឈប់កម្មវិធី តាមធម្មតា Python នឹងបញ្ចេញ `KeyboardInterrupt`។ ប៉ុន្តែ `except:` ទទេៗនេះ បានចាប់យកកំហុសនោះមកទប់ជាប់ ធ្វើឱ្យកម្មវិធីនៅតែរត់គ្មានថ្ងៃបញ្ចប់!

### ២. ការចាប់យកកំហុសច្រើនក្នុងពេលតែមួយ

អ្នកអាចចាប់យក Exceptions ច្រើនប្រភេទព្រមគ្នានៅក្នុង Tuple តែមួយបាន៖

```python
try:
    value = int(input("បញ្ចូលលេខមួយ៖ "))
    print(100 / value)

except (ValueError, ZeroDivisionError) as e:
    print(f"បញ្ហាទិន្នន័យ៖ {e}")
```

### ៣. ភាពខុសគ្នារវាង `raise` និង `return`

អ្នកចាប់ផ្តើមភាគច្រើនតែងតែច្រឡំរវាងការប្រើ `raise` និង `return`។

| `return`      | `raise`           |
| ----------- | --------------- |
| បញ្ចប់មុខងារដោយ**ជោគជ័យ** (Success)     | បញ្ចប់មុខងារព្រោះមាន**កំហុស** (Error)          |
| បញ្ជូន**តម្លៃ** (Sends value) | បញ្ជូន**កំហុស** (Sends Exception) |
| ជាលំហូរធម្មតា (Normal flow) | កាត់ផ្តាច់លំហូរ (Interrupts flow) |

## 💻 ការបំបែកកូដ (Code Breakdown)

### ១. ការពន្យល់ពី Traceback (តើវាជាអ្វី?)

សិស្សតែងតែឆ្ងល់ និងភ័យស្លន់ស្លោពេលឃើញ៖
```text
Traceback (most recent call last):
```
**Traceback មិនមែនជាកំហុសទេ!** វាជាផែនទី (Map) ដែល Python បង្ហាញថា៖ "តើកូដរត់មកពីណា ហើយកំហុសកើតនៅបន្ទាត់ណា?"

**ឧទាហរណ៍៖**
```text
Traceback
↓
main.py line 18
↓
divide()
↓
ZeroDivisionError
```
អ្នកគ្រាន់តែអានវាពីក្រោមមកលើ នោះអ្នកនឹងដឹងភ្លាមថា បញ្ហាចាប់ផ្តើមនៅឯណា។

### ២. អាថ៌កំបាំងរបស់ `finally` ជាមួយ `return` (សំណួរសម្ភាសន៍ការងារ)

នេះជាសំណួរដ៏ពេញនិយមក្នុងការសម្ភាសន៍ (Interview)។ តើកូដនេះបញ្ចេញអ្វី?

```python
def test():
    try:
        return 1
    finally:
        print("Cleaning...")

print(test())
```
**លទ្ធផល Output:**
```text
Cleaning...
1
```
**ការបកស្រាយ៖** `finally` ត្រូវបានដំណើរការ **មុនពេល** ដែលមុខងារ (Function) ពិតជាប្រគល់ `return` ទៅឱ្យខាងក្រៅ។ ទោះបីជាមាន `return` នៅចំកណ្តាល `try` ក៏ `finally` នៅតែទាមទារសិទ្ធិដំណើរការមុនជានិច្ច!

### ៣. ការប្រើ `finally` ជាមួយឯកសារ (Files)

```python
file = None

try:
    file = open("data.txt")
    print(file.read())

finally:
    if file:
        file.close() # បិទ File ដោយសុវត្ថិភាព
```
នេះជាមូលហេតុដែល Python បង្កើត Context Manager (`with open(...)`) ដើម្បីដោះស្រាយរឿងនេះដោយស្វ័យប្រវត្តិ ព្រោះវាខ្លីជាង និងងាយស្រួលជាងការសរសេរ `try...finally` ដោយខ្លួនឯង។

## 🛒 ការអនុវត្តក្នុងពិភពពិត (API Error Handling)

កម្មវិធីទំនើបៗពឹងផ្អែកយ៉ាងខ្លាំងលើការទាញយកទិន្នន័យពី Internet (APIs)។ នេះជារបៀបសរសេរកូដ Backend ពិតប្រាកដ៖

```python
import requests

url = "https://api.github.com/users/octocat"

try:
    response = requests.get(url, timeout=5)
    response.raise_for_status() # នឹងបង្កើតកំហុស បើ Internet មិនជោគជ័យ (ឧ. 404)

except requests.Timeout:
    print("សេវាអុីនធឺណិតដើរយឺតពេក (Timeout)!")

except requests.ConnectionError:
    print("មិនមានសេវាអុីនធឺណិត (No Connection)!")

except requests.HTTPError as e:
    print(f"កំហុសពី Server ផ្ទាល់៖ {e}")
```

## ⭐ ការអនុវត្តដ៏ល្អបំផុត (Best Practices)

- ចាប់យក**តែ**កំហុសណាដែលអ្នករំពឹងទុក (Catch only what you expect)។
- ជៀសវាងការសរសេរ `except:` ទទេៗយ៉ាងដាច់ខាត (Avoid bare except)។
- កុំចាប់យកកំហុសហើយទុកវាចោលស្ងាត់ៗ (Never ignore errors silently) ត្រូវកត់ត្រាវា (Log)។
- បង្កើត Custom Exceptions សម្រាប់ច្បាប់អាជីវកម្មផ្ទាល់ខ្លួន (Business Logic)។
- ប្រើប្រាស់ `with` ជំនួសឱ្យការបិទឯកសារដោយដៃនៅក្នុង `finally` ។
- រក្សាទំហំកូដនៅក្នុង `try` ឱ្យខ្លីបំផុតតាមដែលអាចធ្វើទៅបាន (Keep try blocks small)។

## 🛠️ លំហាត់អនុវត្តន៍ (Practice Exercises)

សាកល្បងចំណេះដឹងរបស់អ្នកជាមួយនឹងលំហាត់ទាំងនេះ!

### លំហាត់ទី១៖ ប្រព័ន្ធផ្ទៀងផ្ទាត់អាយុ
សរសេរកូដសួរអ្នកប្រើប្រាស់ពីអាយុរបស់ពួកគេ។ ប្រសិនបើអាយុជាលេខអវិជ្ជមាន សូមធ្វើឱ្យកម្មវិធីគាំងដោយបញ្ចេញកំហុស `raise ValueError` ជាមួយនឹងសារថា "អាយុមិនអាចអវិជ្ជមានបានទេ"។

### លំហាត់ទី២៖ ការអានឯកសារមានសុវត្ថិភាព
សរសេរកូដដើម្បីបើកឯកសារ `students.txt` ។ ប្រសិនបើមិនមានឯកសារនេះទេ សូមចាប់យកកំហុស `FileNotFoundError` ហើយបង្ហាញសារថា "រកឯកសារមិនឃើញ សូមបង្កើតវាជាមុនសិន" ។

### លំហាត់ទី៣៖ ការត្រួតពិនិត្យលេខសម្ងាត់ (Password Validation)
បង្កើត Custom Exception មួយឈ្មោះថា `InvalidPasswordError` ។ បន្ទាប់មកសរសេរមុខងារមួយដើម្បីត្រួតពិនិត្យ លេខសម្ងាត់។ ប្រសិនបើលេខសម្ងាត់នោះមានប្រវែងខ្លីជាង ៨ តួអក្សរ សូម `raise InvalidPasswordError`!

### លំហាត់ទី៤៖ ម៉ាស៊ីនគិតលេខដ៏រឹងមាំ (Robust Calculator)
បង្កើតកម្មវិធីគិតលេខសាមញ្ញមួយ (បូក ដក គុណ ចែក) ដោយប្រើប្រាស់ `input()` ។ សូមធានាថាកម្មវិធីមិនគាំងដោយសារកំហុសបញ្ចូលអក្សរ (`ValueError`) និងកំហុសចែកលេខនឹងសូន្យ (`ZeroDivisionError`)។

## ✅ ចំណុចសំខាន់ៗដែលត្រូវចាំ (Key Takeaways)

- **`try` block** អនុញ្ញាតឱ្យអ្នកសាកល្បងកូដដែលអាចមានបញ្ហា (Risky Code)។
- **`except` block** អនុញ្ញាតឱ្យអ្នករៀបចំផែនការទប់ទល់នៅពេលបញ្ហាកើតឡើង។ អ្នកអាចចាប់យកកំហុសច្រើនប្រភេទក្នុងពេលតែមួយបាន។
- ប្រើ **`Exception as e`** ដើម្បីទាញយកទិន្នន័យជាក់លាក់ពីកំហុសនោះ។
- **`else` block** នឹងដំណើរការលុះត្រាតែគ្មានកំហុសណាមួយកើតឡើងនៅក្នុង `try` នោះទេ។
- **`finally` block** នឹងដំណើរការជានិច្ច មិនថាមានកំហុសឬអត់ ហើយវានឹងដំណើរការមុនពេលពាក្យបញ្ជា `return` ទៅទៀត!
- ស្វែងយល់ពីរបៀបអាន **Traceback** ដើម្បីរកទីតាំងដើមចមនៃកំហុស បានយ៉ាងឆាប់រហ័ស។
- កុំប្រើប្រាស់ **Bare `except:`** ទទេៗ ព្រោះវាអាចចាប់យកកំហុសប្រព័ន្ធដូចជា `KeyboardInterrupt` ដែលធ្វើឱ្យកម្មវិធីពិបាកគ្រប់គ្រង។

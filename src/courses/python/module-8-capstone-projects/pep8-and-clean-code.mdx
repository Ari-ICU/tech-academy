## 🌐 Overview

*"កូដត្រូវបានអានញឹកញាប់ជាងការសរសេរទៅទៀត។"* នេះជាប្រសាសន៍របស់លោក Guido van Rossum អ្នកបង្កើតភាសា Python។
ប្រសិនបើអ្នកសរសេរកូដដែលកុំព្យូទ័រយល់ តែមនុស្ស (ឬខ្លួនអ្នកនៅ៣ខែក្រោយ) អានមិនយល់ នោះអ្នកមិនទាន់ជាអ្នកសរសេរកម្មវិធីអាជីពនោះទេ។ ដើម្បីដោះស្រាយបញ្ហានេះ សហគមន៍ Python បានបង្កើតច្បាប់រចនាបថមួយឈ្មោះថា **PEP 8 (Python Enhancement Proposal 8)**។
នៅក្នុងមេរៀននេះ យើងនឹងរៀនពីរបៀបសរសេរកូដឱ្យមានសណ្តាប់ធ្នាប់ ងាយអាន និងស្រស់ស្អាត ដែលគេតែងហៅថា **"Pythonic"**។

---

## 📚 Definitions

- **PEP 8:** ឯកសារផ្លូវការដែលណែនាំពីរបៀបរៀបចំកូដ Python ឱ្យមានឯកសណ្ឋាន (Spacing, Naming, Line Length) ទូទាំងពិភពលោក។
- **Clean Code (កូដស្អាត):** កូដដែលងាយស្រួលអាន ងាយស្រួលយល់ និងងាយស្រួលកែប្រែ។ កូដស្អាតមិនត្រូវការ Comment ពន្យល់ច្រើនទេ ព្រោះកូដខ្លួនវាច្បាស់លាស់រួចទៅហើយ (Self-documenting)។
- **Type Hinting:** ការសរសេរប្រាប់ពីប្រភេទអថេរ (int, str, list) នៅក្នុងកូដ ដើម្បីឱ្យកម្មវិធីសរសេរកូដ (IDE) ជួយស្វែងរកកំហុសមុនពេលរត់កូដ។
- **Linting (Linter):** កម្មវិធីដែលស្កេនកូដរបស់អ្នកដោយស្វ័យប្រវត្តិ ដើម្បីរកមើលកំហុស ឬការសរសេរមិនស្របតាមស្តង់ដារ (ឧទាហរណ៍ `flake8` ឬ `pylint`)។

## 💡 The Core Idea

ស្រមៃថា **អ្នកកំពុងអានសៀវភៅមួយក្បាល**។
- **Bad Code:** អក្សរតូចខ្លះធំខ្លះ គ្មានសញ្ញាខណ្ឌ គ្មានការចុះបន្ទាត់ ឈ្មោះតួអង្គប្តូរចុះប្តូរឡើង។ អ្នកប្រាកដជាឈឺក្បាលមិនខាន!
- **Clean Code & PEP 8:** សៀវភៅត្រូវបានរៀបចំជាជំពូកច្បាស់លាស់ ចុះបន្ទាត់ត្រឹមត្រូវ រក្សាទម្រង់អក្សរស្មើគ្នា។ អ្នកអានមួយភ្លែត ដឹងថាសាច់រឿងនិយាយពីអ្វី។ កូដក៏ដូចសៀវភៅដែរ! វាត្រូវតែជាសិល្បៈនៃការទំនាក់ទំនង។

## 📖 In Depth

**គោលការណ៍សំខាន់ៗរបស់ PEP 8:**
1. **ការដាក់ឈ្មោះ (Naming Conventions):**
   - Variables & Functions: `snake_case` (ឧ. `user_age`, `calculate_total()`)
   - Classes: `PascalCase` (ឧ. `UserProfile`, `DatabaseConnection`)
   - Constants (អថេរមិនប្រែប្រួល): `UPPER_SNAKE_CASE` (ឧ. `MAX_RETRIES = 5`)
2. **ការចុះបន្ទាត់ (Indentation):** ប្រើប្រាស់ **ដកឃ្លា ៤ ដង (4 Spaces)** មិនមែនជាការចុច Tab ទេ (ទោះបីជាកម្មវិធីភាគច្រើនប្តូរ Tab ទៅជា 4 spaces ឱ្យក៏ដោយ)។
3. **ប្រវែងបន្ទាត់ (Line Length):** កុំសរសេរកូដវែងជាង **៧៩ តួអក្សរ** ក្នុងមួយបន្ទាត់ ដើម្បីងាយស្រួលមើលលើអេក្រង់។
4. **ការដកឃ្លា (Blank Lines):** ដកឃ្លា ២ បន្ទាត់នៅចន្លោះការប្រកាស Class ឬ Function ធំៗ។

## 💻 Code Breakdown

### ១. ការប្រៀបធៀប Bad Code និង Clean Code

```python
# ❌ កូដដែលមិនល្អ (Bad Code - អានមិនយល់ គ្មានស្តង់ដារ)
class data:
    def __init__(self,X,Y):
        self.X=X
        self.Y=Y
    def Cal(self):
        a = 0
        for i in self.X:
            a += i * self.Y
        return a

d = data([1,2,3], 5)
print(d.Cal())


# ✅ កូដដែលល្អ (Clean Code ស្របតាម PEP 8)
class SalesData:
    """Class សម្រាប់ផ្ទុកទិន្នន័យលក់ និងការគណនា"""
    
    def __init__(self, quantities, price):
        self.quantities = quantities
        self.price = price
        
    def calculate_total_revenue(self):
        """គណនាចំណូលសរុប"""
        total_revenue = 0
        for quantity in self.quantities:
            total_revenue += quantity * self.price
            
        return total_revenue

sales = SalesData(quantities=[1, 2, 3], price=5)
print(sales.calculate_total_revenue())
```

### ២. ការប្រើប្រាស់ Type Hinting (Python 3.5+)

ការសរសេរ Type Hinting ធ្វើឱ្យកូដរបស់អ្នកមើលទៅមានលក្ខណៈអាជីព និងជួយឱ្យសមាជិកក្រុមមិនចាំបាច់ស្មានថាតើទិន្នន័យនោះជាអ្វី។

```python
from typing import List, Dict, Optional

# ❌ មិនមាន Type Hinting (យើងមិនដឹងថា user_id ជាលេខ ឬអក្សរទេ)
def get_user_data(user_id):
    pass

# ✅ មាន Type Hinting 
# ប្រាប់ថា user_id ត្រូវតែជាអក្សរ (str)
# ហើយលទ្ធផលដែលបញ្ចេញមកវិញ គឺ Dictionary (str ជួប int) ឬក៏ គ្មានទិន្នន័យ (None)
def get_user_profile(user_id: str) -> Optional[Dict[str, int]]:
    
    # ឧបមាថាទៅទាញយកពី Database...
    if user_id == "admin_001":
        return {"age": 30, "score": 9500}
    
    # បើរកមិនឃើញ ប្រគល់ None មកវិញ
    return None

# ពេលយើងវាយកូដ 'profile = get_user_profile(123)' ក្នុង VS Code
# វានឹងគូសបន្ទាត់ក្រហមប្រាប់ភ្លាម ព្រោះយើងបញ្ចូលលេខ(int) ជំនួសឱ្យអក្សរ(str)
```

### ៣. ជំនួយការរៀបចំកូដ (Auto-Formatters)

អ្នកមិនចាំបាច់អង្គុយរាប់ដកឃ្លាដោយខ្លួនឯងរាល់ពេលសរសេរកូដនោះទេ! ពិភពលោកបច្ចុប្បន្នប្រើកម្មវិធីរៀបចំកូដដោយស្វ័យប្រវត្តិ។ កម្មវិធីដែលល្បីជាងគេគឺ **`Black`**។

## 🌐 ការអនុវត្តជាក់ស្តែង (Real-world Application)

**សរសេរកូដបែប 'Pythonic' ជាជាងកូដ C/Java**

Pythonic មានន័យថា ការសរសេរកូដដោយប្រើលក្ខណៈពិសេសរបស់ Python ផ្ទាល់ដើម្បីឱ្យកូដខ្លី និងមានប្រសិទ្ធភាព។ នេះជាឧទាហរណ៍នៃការកែលម្អកូដ៖

```python
# គោលដៅ: រកមើលថាតើមានអ្នកឈ្មោះ "Sok" ក្នុងបញ្ជីឬទេ

names = ["Dara", "Bopha", "Sok", "Chea"]

# ❌ ទម្រង់អ្នកទើបចេះសរសេរ (សរសេរដូចភាសា C)
found = False
for i in range(len(names)):
    if names[i] == "Sok":
        found = True
        break
print(found)

# ✅ ទម្រង់ Pythonic (ខ្លី ងាយអាន)
is_sok_here = "Sok" in names
print(is_sok_here)
```

```python
# គោលដៅ: ភ្ជាប់ឈ្មោះកុំព្យូទ័រជាបន្តបន្ទាប់

servers = ["server1", "server2", "server3"]

# ❌ កូដរញ៉េរញ៉ៃ (ប្រើ Memory ច្រើន)
result = ""
for s in servers:
    result += s + ", "
result = result[:-2] # លុបសញ្ញាក្បៀសចុងក្រោយចោល

# ✅ ទម្រង់ Pythonic (ប្រើប្រាស់ .join())
result = ", ".join(servers)
```

## ❌ Common Mistakes

- **ប្រើ `l`, `O`, ឬ `I` ជាឈ្មោះអថេរ:** អក្សរតូច `l` មើលទៅដូចលេខ `1`, អក្សរធំ `O` ដូចលេខ `0`។ កុំប្រើពួកវាជាឈ្មោះអថេរឱ្យសោះ ព្រោះវាធ្វើឱ្យច្រឡំភ្នែក។
- **ដាក់ Comment ច្រើនលើសលុប:** ការពន្យល់រាល់បន្ទាត់ ដូចជា `# បូកលេខចូលគ្នា` បន្ទាប់មក `x = a + b` គឺជារឿងមិនចាំបាច់។ ត្រូវប្រើ Comment សម្រាប់ពន្យល់ថា **"ហេតុអ្វី (Why)"** មិនមែនពន្យល់ថា **"ធ្វើអ្វី (What)"** នោះទេ (ព្រោះកូដខ្លួនវាប្រាប់រួចហើយ)។
- **លាយឡំ Tab និង Space:** ក្នុង Python បើអ្នកលាយឡំការប្រើ Tab Key និងការចុច Space bar ចំនួន ៤ដង ក្នុងឯកសារតែមួយ កម្មវិធីរបស់អ្នកនឹងលោត `IndentationError` ភ្លាមៗ (ទោះបីជាមើលនឹងភ្នែកឃើញស្មើគ្នាក៏ដោយ)។ ត្រូវកំណត់ Editor (VS Code) ឱ្យប្តូរ Tab ទៅជា 4 Spaces ជានិច្ច។

## ✅ Key Takeaways

- គោរពតាម **PEP 8** ដើម្បីឱ្យកូដរបស់អ្នកមើលទៅប្រកបដោយវិជ្ជាជីវៈ (Professional)។
- ប្រើប្រាស់ **`snake_case`** សម្រាប់អនុគមន៍/អថេរ និង **`PascalCase`** សម្រាប់ថ្នាក់ (Classes)។
- អនុវត្តន៍ការដាក់ **Type Hinting** ជានិច្ច ព្រោះវាជួយឱ្យមិត្តរួមការងារ និង Editor របស់អ្នក (ដូចជា VS Code) យល់ពីទិន្នន័យបានច្បាស់លាស់។
- កុំចំណាយពេលរៀបចំកូដដោយផ្ទាល់ដៃ ត្រូវប្រើប្រាស់ Auto-Formatters ដូចជា **`Black`** ដើម្បីរៀបចំកូដដោយស្វ័យប្រវត្តិពេលអ្នកចុច Save។

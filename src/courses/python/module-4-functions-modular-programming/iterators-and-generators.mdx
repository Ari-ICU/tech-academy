## 🌐 Overview

ស្រមៃថាអ្នកមានឯកសារអត្ថបទដ៏ធំមួយទំហំ 10GB។ បើអ្នកប្រើប្រាស់កូដ `file.read()` ធម្មតាដើម្បីអានឯកសារនេះ កុំព្យូទ័ររបស់អ្នកដែលមាន RAM ត្រឹមតែ 8GB នឹងគាំង (Crash) ភ្លាមៗ ព្រោះវាគ្មានកន្លែងផ្ទុកទិន្នន័យទាំងអស់នោះក្នុងពេលតែមួយទេ។ 
នេះគឺជាពេលដែល **Generators** ចូលមកជួយសង្គ្រោះ! នៅក្នុង Python, Generators គឺជាអាវុធសម្ងាត់សម្រាប់គ្រប់គ្រងទិន្នន័យរាប់លានជួរដោយប្រើប្រាស់ Memory (RAM) ស្ទើរតែស្មើសូន្យ។ វាត្រូវបានប្រើប្រាស់យ៉ាងទូលំទូលាយនៅក្នុង Data Science និងការអភិវឌ្ឍន៍ប្រព័ន្ធខ្នាតធំ។

## 📚 Definitions

- **Iterable (អាចរាប់បាន):** វត្ថុដែលអាចប្រើក្នុង `for` loop បាន (ឧ. List, String, Tuple)។
- **Iterator (អ្នករាប់):** វត្ថុដែលមានភ្ជាប់ជាមួយអនុគមន៍ `__next__()` ដើម្បីប្រាប់ថា "តើមានអ្វីបន្ទាប់ទៀត?"
- **Generator (ម៉ាស៊ីនបង្កើត):** ជាប្រភេទពិសេសរបស់ Iterator ដែលត្រូវបានបង្កើតឡើងយ៉ាងងាយស្រួលដោយប្រើប្រាស់អនុគមន៍ដែលមានផ្ទុកពាក្យ `yield`។
- **`yield` Keyword:** ប្រើប្រាស់ជំនួសឱ្យ `return` ដើម្បីបញ្ជូនតម្លៃចេញមកក្រៅ ប៉ុន្តែវាមិនបញ្ចប់អនុគមន៍ទេ វាគ្រាន់តែ "ផ្អាក" (Pause) ជាបណ្តោះអាសន្នប៉ុណ្ណោះ។
- **Lazy Evaluation:** ជាទស្សនៈវិជ្ជាក្នុងការសរសេរកម្មវិធី ដែលមានន័យថា "កុំទាន់ធ្វើការងារ លុះត្រាតែមានគេត្រូវការលទ្ធផលនោះជាចាំបាច់"។

## 💡 The Core Idea

ស្រមៃថាអ្នកចង់បាន **ភីហ្សា ១០០០ នំ** សម្រាប់កម្មវិធីជប់លៀងធំមួយ។
- **ការប្រើ List (Return):** អ្នកបញ្ជាទិញភីហ្សាទាំង ១០០០ នំ ឱ្យគេដឹកមកក្នុងពេលតែមួយ។ ផ្ទះរបស់អ្នកនឹងគ្មានកន្លែងទុកទេ (Memory ពេញ) ហើយភីហ្សានឹងត្រជាក់អស់។
- **ការប្រើ Generator (Yield):** អ្នកជួលចុងភៅម្នាក់មកផ្ទះ។ ពេលភ្ញៀវម្នាក់ដើរមក គាត់ហៅ **`next(ចុងភៅ)`** នោះចុងភៅនឹងដុតភីហ្សាមួយ **(`yield`)** ហើយហុចឱ្យ។ ចុងភៅសម្រាករហូតដល់មានភ្ញៀវបន្ទាប់។ វិធីនេះ ទោះមានភ្ញៀវ ១លាននាក់ ក៏អ្នកត្រូវការកន្លែងទុកភីហ្សាតែមួយដែរ! (Memory មិនពេញឡើយ)។

## 📖 In Depth

**ការប្រៀបធៀបរវាង List Comprehension និង Generator Expression:**
អ្នកប្រហែលជាធ្លាប់ប្រើ `[x * 2 for x in range(10)]` ដែលប្រើរង្វង់ក្រចកជ្រុង។ នេះបង្កើត List។ 
ប្រសិនបើអ្នកប្តូរទៅប្រើរង្វង់ក្រចកមូល `(x * 2 for x in range(10))` វានឹងបង្កើតជា Generator Object ដែលមិនទាន់ដំណើរការគណនាទេ រហូតទាល់តែអ្នក Loop ឆ្លងកាត់វា។

**របៀបដំណើរការ Generator:**
- អ្នកមិនអាចប្រើប្រាស់លេខ Index ដើម្បីទាញយកទិន្នន័យពី Generator ទេ (ឧទាហរណ៍ `gen[0]` គឺ Error)។
- អ្នកអាចអានវាបានតែ **ម្តងគត់** (One-way street)។ បើអានដល់ទីបញ្ចប់ហើយ វាត្រូវអស់រលីង។ បើចង់បានទៀត ត្រូវបង្កើតវាថ្មី។

## 💻 Code Breakdown

```python
# ឧទាហរណ៍ទី១: ភាពខុសគ្នារវាង Return និង Yield
def count_with_return():
    print("ចាប់ផ្តើម Return...")
    return 1
    return 2 # កូដនេះគ្មានអ្នកណាអើពើទេ ព្រោះអនុគមន៍ស្លាប់តាំងពីបន្ទាត់ទី១

def count_with_yield():
    print("ចាប់ផ្តើម Yield...")
    yield 1
    yield 2
    yield 3

print("--- លទ្ធផល Return ---")
print(count_with_return())

print("\n--- លទ្ធផល Yield ---")
gen = count_with_yield() # វាមិនទាន់ដំណើរការ print ទេ វាគ្រាន់តែបង្កើត Object សិន
print(next(gen)) # លោតអក្សរ 'ចាប់ផ្តើម Yield...' រួចបញ្ជូនលេខ 1 មកក្រៅ ហើយផ្អាក
print(next(gen)) # ដំណើរការបន្ត បញ្ជូនលេខ 2 រួចផ្អាក
print(next(gen)) # បញ្ជូនលេខ 3 
# បើអ្នក print(next(gen)) ម្តងទៀត វានឹងលោត Error "StopIteration"
```

```python
# ឧទាហរណ៍ទី២: ហេតុអ្វី Generator សំខាន់? (ការសន្សំសំចៃ Memory)
import sys

# បង្កើត List នៃលេខ 1 ដល់ 1លាន
list_numbers = [x for x in range(1000000)]

# បង្កើត Generator នៃលេខ 1 ដល់ 1លាន
gen_numbers = (x for x in range(1000000))

# ឆែកមើលទំហំ Memory ដែលពួកវាស៊ី (គិតជា Bytes)
print(f"ទំហំរបស់ List: {sys.getsizeof(list_numbers):,} bytes") 
# លទ្ធផលប្រហែល: 8,448,728 bytes (ស៊ីទំហំធំ)

print(f"ទំហំរបស់ Generator: {sys.getsizeof(gen_numbers):,} bytes")
# លទ្ធផលប្រហែល: 104 bytes (តូចមែនទែន!) ព្រោះវាចាំតែរូបមន្តប៉ុណ្ណោះ
```

```python
# ឧទាហរណ៍ទី៣: ការបង្កើត Infinite Sequence (លេខមិនចេះអស់)
def infinite_even_numbers():
    n = 0
    while True:
        yield n
        n += 2

# បើអ្នកប្រើ List ជាមួយនឹង while True កុំព្យូទ័រអ្នកនឹងគាំងភ្លាម! តែ Generator អត់អីទេ
evens = infinite_even_numbers()
for i in range(5): # យើងទាញយកតែ ៥ ដង
    print(next(evens)) 
# លទ្ធផល: 0, 2, 4, 6, 8
```

## 🌐 ការអនុវត្តជាក់ស្តែង (Real-world Application)

**ការអានឯកសារ Log ដែលមានទំហំធំមហិមា (Large File Processing)**

ឧបមាថាអ្នកមានឯកសារ `server_logs.txt` ទំហំ 50GB ហើយអ្នកចង់ស្វែងរកតែបន្ទាត់ណាដែលមានពាក្យ "ERROR" ប៉ុណ្ណោះ។ អ្នកមិនអាច `read()` វាចូល List បានទេ។

```python
def read_large_file(file_path):
    """Generator សម្រាប់អានឯកសារម្តងមួយបន្ទាត់"""
    with open(file_path, 'r') as file:
        for line in file:
            yield line

def get_errors_only(log_lines):
    """Generator សម្រាប់ត្រងយកតែបន្ទាត់ Error"""
    for line in log_lines:
        if "ERROR" in line:
            yield line.strip()

# របៀបប្រើប្រាស់តជាជួរ (Pipeline)
# វាដើរម្តងមួយបន្ទាត់ពីលើដល់ក្រោម Memory ស៊ីត្រឹមតែប៉ុន្មាន KB ប៉ុណ្ណោះទោះ File ធំប៉ុណ្ណាក៏ដោយ
logs = read_large_file('server_logs.txt')
error_logs = get_errors_only(logs)

# ដំណើរការទាញយកទិន្នន័យ (Lazy Evaluation ចាប់ផ្តើមធ្វើការនៅពេលនេះ)
for i, error in enumerate(error_logs):
    print(f"រកឃើញ Error: {error}")
    if i >= 4: # បង្ហាញត្រឹម ៥ Error ដំបូង រួចបញ្ឈប់
        break
```

  ```python
  gen = (x for x in range(3))
  print(list(gen)) # [0, 1, 2]
  print(list(gen)) # [] (ទទេស្អាត! ព្រោះ Generator ត្រូវប្រើអស់ហើយ)
  ```
  បើអ្នកចង់អានវាម្តងទៀត អ្នកត្រូវបង្កើត `gen` ឡើងវិញ។ បើអ្នកត្រូវការអានវាចុះឡើងច្រើនដង អ្នកគួរតែបំប្លែងវាទៅជា List សិន (បើទិន្នន័យមិនធំពេក)។
- **ព្យាយាមប្រើ `len()` លើ Generator:** Generator ខ្លួនវាមិនដឹងថាវាមានទិន្នន័យចំនួនប៉ុន្មាននោះទេ រហូតទាល់តែវាបង្កើតទិន្នន័យនោះអស់។ ដូច្នេះ `len(gen)` នឹងលោត Error `TypeError`។

---

## ✅ Key Takeaways

- ប្រើ **`yield`** ជំនួសឱ្យ `return` ដើម្បីបង្កើត **Generator Function** ដែលអាចផ្អាក និងដំណើរការបន្តបាន។
- លក្ខណៈពិសេសរបស់ Generator គឺ **Lazy Evaluation** (ធ្វើការតែពេលចាំបាច់) ដែលជួយសន្សំសំចៃ Memory បានយ៉ាងអស្ចារ្យ។
- ប្រើប្រាស់ **Generator Expressions** (រង្វង់ក្រចកមូល `()`) ជាជំនួស List Comprehensions (រង្វង់ក្រចកជ្រុង `[]`) នៅពេលអ្នកធ្វើការជាមួយទិន្នន័យធំៗរាប់ម៉ឺនជួរ។
- ចងចាំថា Generator គឺដូចជាស្ទឹងដែលហូរទៅមុខជានិច្ច អ្នកមិនអាចអានទិន្នន័យដែលហួសហើយឡើងវិញបានទេ លុះត្រាតែអ្នកចាប់ផ្តើមស្ទឹងនោះថ្មី។

## 🌐 Overview

ពេលអ្នកសរសេរកូដបាន ១០០ បន្ទាត់ អ្នកអាចរត់វាហើយមើលលទ្ធផលដោយភ្នែកបានយ៉ាងងាយ។ ប៉ុន្តែចុះបើកូដរបស់អ្នកមាន **១០ម៉ឺនបន្ទាត់**? តើអ្នកដឹងដោយរបៀបណាថា ការកែប្រែកូដបន្តិចបន្តួចនៅថ្ងៃនេះ មិនធ្វើឱ្យខូចខាតដល់មុខងារចាស់ៗដែលធ្លាប់តែដើរស្រួលនោះ?
**Automated Testing (ការតេស្តដោយស្វ័យប្រវត្តិ)** គឺជាចម្លើយ។ វាប្រៀបដូចជាអ្នកមានមនុស្សយន្តរាប់ពាន់នាក់ ឈរចាំឆែកមើលគ្រប់អនុគមន៍ទាំងអស់រាល់ពេលអ្នកចុច Save។ នៅក្នុងមេរៀននេះ យើងនឹងរៀនប្រើ **`pytest`** ដែលជាបណ្ណាល័យសាកល្បងកូដដ៏មានអំណាចបំផុតនៅក្នុងពិភព Python។

## 📚 Definitions

- **Unit Testing:** ការសាកល្បងកូដជាចំណែកតូចៗបំផុត (ដូចជាអនុគមន៍នីមួយៗ) ដាច់ដោយឡែកពីគ្នា។
- **TDD (Test-Driven Development):** ជាទស្សនៈវិជ្ជាសរសេរកូដ ដែលតម្រូវឱ្យអ្នកសរសេរកូដតេស្ត **មុនពេល** សរសេរកូដពិតប្រាកដ។ វាជួយឱ្យកូដរបស់អ្នកមានគោលដៅច្បាស់លាស់។
- **`assert`:** ជាពាក្យគន្លឹះរបស់ Python សម្រាប់អះអាងការពិត។ ឧ. `assert 1 + 1 == 2`។ បើវាពិត កម្មវិធីដើរធម្មតា។ បើវាខុស កម្មវិធីនឹងគាំង (AssertionError)។
- **`pytest`:** ជា Third-party Library (ត្រូវ `pip install`) ដែលធ្វើឱ្យការសរសេរ និងរត់តេស្តមានភាពងាយស្រួលជាង `unittest` ដែលមានស្រាប់ក្នុង Python ឆ្ងាយណាស់។
- **Fixture:** នៅក្នុង Pytest គឺជាទិន្នន័យ ឬបរិស្ថានដែលត្រូវបានរៀបចំទុកជាមុន សម្រាប់ឱ្យអនុគមន៍តេស្តនីមួយៗយកទៅប្រើ (ឧទាហរណ៍: ការបើក Database Connection)។

## 💡 The Core Idea

ស្រមៃថា **អ្នកជារោងចក្រផលិតរថយន្ត**។
- **ការមិនធ្វើតេស្ត:** អ្នកដំឡើងរថយន្តទាំងមូលរួចរាល់ រួចយកវាទៅបើកសាកល្បង។ បើវាឆេះ អ្នកមិនដឹងថាវាមកពីម៉ាស៊ីន ភ្លើង ឬហ្វ្រាំងនោះទេ (ពិបាករកកំហុស)។
- **Unit Testing:** អ្នកតេស្ត **កង់** ដាច់ដោយឡែក អ្នកតេស្ត **ម៉ាស៊ីន** លើតុពិសោធន៍ អ្នកតេស្ត **ហ្វ្រាំង** ដាច់ដោយឡែក។ ពេលអ្វីៗគ្រប់យ៉ាងដំណើរការល្អ ទើបអ្នកផ្គុំវាចូលគ្នា។ បើមានបញ្ហា អ្នកដឹងច្បាស់ថាខូចនៅត្រង់ណាភ្លាមៗ!

## 📖 In Depth

**រចនាសម្ព័ន្ធនៃកូដតេស្ត (AAA Pattern):**
អ្នកជំនាញតែងតែសរសេរកូដតេស្តតាមទម្រង់ ៣ ជំហាន (Arrange, Act, Assert):
1. **Arrange (រៀបចំ):** រៀបចំទិន្នន័យ (Input)។
2. **Act (អនុវត្ត):** ហៅអនុគមន៍ដែលចង់តេស្ត។
3. **Assert (អះអាង):** ផ្ទៀងផ្ទាត់លទ្ធផល។

**របៀបដាក់ឈ្មោះឯកសារ និងអនុគមន៍តេស្ត:**
Pytest ដើរស្វែងរកឯកសារតេស្តដោយស្វ័យប្រវត្តិ។ ដូច្នេះ អ្នក **ត្រូវតែ** ដាក់ឈ្មោះឯកសារផ្តើមដោយ `test_` (ឧ. `test_math.py`) និងឈ្មោះអនុគមន៍តេស្តផ្តើមដោយ `test_` (ឧ. `def test_add():`)។

## 💻 Code Breakdown

ជាដំបូង ត្រូវប្រាកដថាអ្នកបានដំឡើង Pytest: 
`pip install pytest`

```python
# ឯកសារទី១: calculator.py (កូដពិតប្រាកដដែលអ្នកសរសេរ)
def add(a, b):
    return a + b

def divide(a, b):
    if b == 0:
        raise ValueError("មិនអាចចែកនឹងសូន្យបានទេ!")
    return a / b
```

```python
# ឯកសារទី២: test_calculator.py (កូដសម្រាប់តេស្ត calculator.py)
import pytest
from calculator import add, divide

# តេស្តទី១: តេស្តការបូកលេខធម្មតា
def test_add_positive_numbers():
    # Arrange (រៀបចំ)
    a, b = 2, 3
    
    # Act (អនុវត្ត)
    result = add(a, b)
    
    # Assert (អះអាង)
    assert result == 5, "២ បូក ៣ ត្រូវតែស្មើ ៥"

# តេស្តទី២: តេស្តការបូកលេខអវិជ្ជមាន
def test_add_negative_numbers():
    assert add(-2, -3) == -5

# តេស្តទី៣: តេស្តករណីពិសេស (Edge Cases - ការចែកនឹងសូន្យ)
def test_divide_by_zero():
    # យើងរំពឹងថា ValueError នឹងលោតឡើង ពេលយើងចែកនឹងសូន្យ
    # បើវាលោតមែន មានន័យថាតេស្តនេះ ជោគជ័យ (Passed)
    with pytest.raises(ValueError, match="មិនអាចចែកនឹងសូន្យបានទេ!"):
        divide(10, 0)
```

**របៀបដំណើរការ:**
បើក Terminal រួចវាយពាក្យ `pytest` នៅក្នុង folder នោះ។ Pytest នឹងរត់តេស្តទាំងអស់ ហើយបង្ហាញលទ្ធផលពណ៌បៃតង (Passed) ឬពណ៌ក្រហម (Failed)។

```python
# ឧទាហរណ៍ទី៣: ការប្រើប្រាស់ Pytest Fixtures
import pytest

# Fixture គឺដូចជាជំនួយការរៀបចំទិន្នន័យឱ្យអ្នក
@pytest.fixture
def empty_shopping_cart():
    # កូដនេះនឹងរត់រាល់ពេលតេស្តណាមួយហៅប្រើប្រាស់វា
    return []

# អនុគមន៍តេស្តនេះ ទាមទារជំនួយការ empty_shopping_cart
def test_add_item_to_cart(empty_shopping_cart):
    cart = empty_shopping_cart # ទទួលបាន []
    cart.append("ផ្លែប៉ោម")
    
    assert len(cart) == 1
    assert cart[0] == "ផ្លែប៉ោម"
```

## 🌐 ការអនុវត្តជាក់ស្តែង (Real-world Application)

**ការការពារការបំប្លែងទិន្នន័យខុស (Data Pipeline Testing)**

ក្នុង Data Science បើអនុគមន៍បំប្លែងទិន្នន័យរបស់អ្នកសរសេរខុស កម្មវិធី AI របស់អ្នកនឹងរៀនពីទិន្នន័យខុស (Garbage In, Garbage Out)។ យើងត្រូវតេស្តវាឱ្យបានហ្មត់ចត់៖

```python
import pytest
import pandas as pd

# អនុគមន៍ពិតប្រាកដដែលយើងចង់តេស្ត
def clean_prices(price_list):
    """បំប្លែង [' $10.5 ', 'N/A', ' 20 '] ទៅជា [10.5, 0.0, 20.0]"""
    cleaned = []
    for p in price_list:
        if p == 'N/A':
            cleaned.append(0.0)
        else:
            # លុបចន្លោះទទេ និងសញ្ញា $ ចេញ រួចប្តូរជា Float
            num = float(p.strip().replace('$', ''))
            cleaned.append(num)
    return cleaned

# កូដតេស្ត
def test_clean_prices_standard():
    raw_data = [' $10.5 ', ' 20 ']
    expected = [10.5, 20.0]
    assert clean_prices(raw_data) == expected

def test_clean_prices_missing_data():
    raw_data = ['N/A', '$5']
    expected = [0.0, 5.0]
    assert clean_prices(raw_data) == expected

def test_clean_prices_invalid_input():
    # តើវានឹងមានអ្វីកើតឡើង បើគេបញ្ចលអក្សរធម្មតា?
    # វាគួរបង្ហាញ Error (ValueError របស់ Float)
    with pytest.raises(ValueError):
        clean_prices(["ដប់ដុល្លារ"])
```
ការសរសេរតេស្តបែបនេះ ផ្តល់ទំនុកចិត្ត ១០០% ដល់អ្នក មុននឹងយកអនុគមន៍ `clean_prices` នេះទៅដំណើរការលើទិន្នន័យរាប់លានជួរ។

## ❌ Common Mistakes

- **មិនសរសេរតេស្តសោះ:** អ្នកអភិវឌ្ឍន៍ថ្មីៗគិតថា "ការសរសេរតេស្តស៊ីពេលណាស់"។ ផ្ទុយទៅវិញ ការមិនសរសេរតេស្ត នឹងធ្វើឱ្យអ្នកខាតពេលរាប់ថ្ងៃក្នុងការស្វែងរក Bugs នៅពេលកម្មវិធីរបស់អ្នកកាន់តែធំ។ (សរសេរតេស្ត = សន្សំពេលនៅថ្ងៃអនាគត)។
- **តេស្តរបស់ដែលមិនចាំបាច់:** កុំសរសេរតេស្តដើម្បីពិនិត្យមើលថាអនុគមន៍ `sum()` របស់ Python ដំណើរការឬអត់ (អ្នកបង្កើត Python បានតេស្តវារួចហើយ)។ ចូរតេស្តតែ **កូដ (Logic)** ដែលអ្នកសរសេរដោយខ្លួនឯងប៉ុណ្ណោះ។
- **តេស្តតែករណីដែលដើរ (Happy Path):** បើអ្នកសរសេរអនុគមន៍គណនាអាយុ អ្នកមិនត្រឹមតែតេស្តឆ្នាំ `1995` ទេ អ្នកត្រូវតេស្តឆ្នាំអនាគត `2050` (គួរលោត Error) ឬឆ្នាំដែលបញ្ចូលខុសទម្រង់ (Edge Cases) ទើបជាការតេស្តដ៏ល្អ។

## ✅ Key Takeaways

- **Unit Testing** ការពារអ្នកពីការបង្កើតកំហុស (Bugs) ថ្មីៗ នៅពេលអ្នកកែប្រែកូដចាស់ៗ។
- ប្រើប្រាស់ **`pytest`** ជាស្តង់ដារ ព្រោះវាមានកូដខ្លី ងាយស្រួលសរសេរ និងបង្ហាញកំហុសបានច្បាស់លាស់។
- ប្រើប្រាស់ពាក្យគន្លឹះ **`assert`** ដើម្បីផ្ទៀងផ្ទាត់លទ្ធផល។ ប្រសិនបើ `assert` ចេញ True តេស្តរបស់អ្នកជោគជ័យ។
- រៀបចំកូដតេស្តតាមក្បួន **AAA (Arrange, Act, Assert)** ដើម្បីឱ្យវាមានរបៀបរៀបរយ និងងាយស្រួលអានសម្រាប់សមាជិកក្រុម។

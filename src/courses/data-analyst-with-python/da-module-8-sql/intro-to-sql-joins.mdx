## 🌐 សេចក្តីផ្តើម (Overview)

នៅក្នុង Database ពិតប្រាកដ តារាងត្រូវបានបំបែកចេញពីគ្នា ដើម្បីកុំអោយទិន្នន័យស្ទួន។
- **តារាង `Customers`:** `customer_id`, `name`, `city`
- **តារាង `Orders`:** `order_id`, `customer_id` (អ្នកណាទិញ?), `amount`

ពេលថៅកែសួរថា "តើអតិថិជនឈ្មោះអ្វី ទិញអស់លុយប៉ុន្មាន?" អ្នកមិនអាចរកចម្លើយក្នុងតារាងតែមួយបានទេ។ អ្នកត្រូវ **JOIN (ភ្ជាប់)** វាបញ្ចូលគ្នា!

## 💻 ការបំបែកកូដ (Code Breakdown)

### ១. អ្វីទៅជាការភ្ជាប់ (Keys)

តារាងទាំងពីរអាចភ្ជាប់គ្នាបាន លុះត្រាតែវាមាន "ស្ពាន" ទាក់ទងគ្នា។ ក្នុងឧទាហរណ៍ខាងលើ ស្ពាននោះគឺជួរឈរ **`customer_id`** ដែលមានវត្តមានក្នុងតារាងទាំងពីរ។

### ២. INNER JOIN (ចំណុចប្រសព្វ)

ទាញយកតែទិន្នន័យណាដែលស៊ីគ្នា ១០០% ប៉ុណ្ណោះ។ (យកតែអតិថិជនណាដែលបានកុម្ម៉ង់)។

```sql
SELECT Customers.name, Orders.amount
FROM Customers
INNER JOIN Orders 
    ON Customers.customer_id = Orders.customer_id;
```
**លទ្ធផល:**
| name | amount |
| :--- | :--- |
| សុខ | 500 |
| សៅ | 300 |
*(ចំណាំ៖ បើ វ៉ាន់ ចុះឈ្មោះជាអតិថិជន តែកត់មិនទាន់ទិញអ្វីសោះ នោះឈ្មោះ វ៉ាន់ នឹងមិនលេចចេញមកទេ)*

### ៣. LEFT JOIN (រក្សាភាពដើមនៃតារាងឆ្វេង)

ចុះបើចង់ឃើញឈ្មោះ "វ៉ាន់" ដែរ ទោះបីគាត់អត់ទិញក៏ដោយ? យើងត្រូវប្រើ LEFT JOIN ដោយដាក់ Customers ជាតារាងគោល (ខាងឆ្វេង)។

```sql
/* តារាងឆ្វេង គឺតារាងដែលនៅក្រោយពាក្យ FROM */
SELECT Customers.name, Orders.amount
FROM Customers
LEFT JOIN Orders 
    ON Customers.customer_id = Orders.customer_id;
```
**លទ្ធផល:**
| name | amount |
| :--- | :--- |
| សុខ | 500 |
| សៅ | 300 |
| វ៉ាន់ | NULL |  <-- ឃើញទេ! គាត់ចេញមកហើយ តែលុយគឺ NULL

### ៤. ការប្រើប្រាស់ឈ្មោះកាត់ (Aliases សម្រាប់តារាង)

ការសរសេរ `Customers.customer_id` គឺវែងណាស់។ អ្នកសរសេរកូដចូលចិត្តតាងឈ្មោះកាត់អោយតារាង ដោយប្រើអក្សរមួយតួ។

```sql
/* តាង Customers ថា C, និង Orders ថា O */
SELECT C.name, O.amount
FROM Customers C
JOIN Orders O       -- JOIN ធម្មតា មានន័យថា INNER JOIN
    ON C.customer_id = O.customer_id;
```

សូមអបអរសាទរ! នេះគឺជាចំណុចកំពូលនៃ SQL។ អ្នកឥឡូវនេះមានសមត្ថភាពគ្រប់គ្រាន់ក្នុងការទាញយកទិន្នន័យរាប់លានជួរ ពីក្រុមហ៊ុនធំៗបានហើយ! តោះទៅអនុវត្តក្នុង Mini Project!

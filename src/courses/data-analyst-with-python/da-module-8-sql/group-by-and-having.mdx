## 🌐 សេចក្តីផ្តើម (Overview)

អ្នកធ្លាប់រៀនយន្តការ "Split-Apply-Combine" ក្នុង Pandas រួចមកហើយ។ ក្នុង SQL វាដំណើរការដូចគ្នាទាំងស្រុង! វាជួយឆ្លើយសំណួរដូចជា៖ "តើអតិថិជនម្នាក់ៗ ចំណាយលុយសរុបប៉ុន្មាន?" ឫ "តើថ្ងៃណាលក់ដាច់ជាងគេ?"។

## 💻 ការបំបែកកូដ (Code Breakdown)

យើងមានតារាង `Sales` ដែលមាន `branch` (សាខា) និង `amount` (ទឹកប្រាក់លក់)។

### ១. ការប្រើប្រាស់ GROUP BY

យើងចង់ដឹងចំណូលសរុបប្រចាំសាខានីមួយៗ។

```sql
/* ជ្រើសរើសជួរឈរ branch រួចធ្វើការបូកសរុប amount */
SELECT branch, SUM(amount) AS total_revenue
FROM Sales
GROUP BY branch; -- ប្រាប់អោយវាចែកជាក្រុមតាមសាខា
```
**លទ្ធផល:**
| branch | total_revenue |
| :--- | :--- |
| Phnom Penh | 5000 |
| Siem Reap | 3000 |

### ២. បន្ថែមការរៀបលំដាប់ (ORDER BY)

តើសាខាណាលក់ដាច់ជាងគេ?

```sql
SELECT branch, SUM(amount) AS total_revenue
FROM Sales
GROUP BY branch
ORDER BY total_revenue DESC; -- រៀបពីធំមកតូច
```

### ៣. ភាពខុសគ្នារវាង WHERE និង HAVING

ឧបមាថាថៅកែចង់ផ្តល់រង្វាន់ដល់សាខាណាដែលរកចំណូលសរុបបាន **លើសពី $4000**។ តើយើងត្រូវសរសេរយ៉ាងម៉េច?

**ខុស ❌ (ប្រើ WHERE):**
```sql
SELECT branch, SUM(amount) AS total_revenue
FROM Sales
WHERE SUM(amount) > 4000 -- Error! WHERE មិនស្គាល់ SUM() ទេ
GROUP BY branch;
```

**ត្រឹមត្រូវ ✅ (ប្រើ HAVING):**
```sql
SELECT branch, SUM(amount) AS total_revenue
FROM Sales
GROUP BY branch
HAVING SUM(amount) > 4000; -- អនុញ្ញាត! ព្រោះវាច្រោះក្រោយពេល Group រួច
```

**ឧទាហរណ៍ប្រើទាំងពីរចូលគ្នា (Advanced):**
រកចំណូលសរុបតាមសាខា ដោយរាប់បញ្ចូលតែការលក់ **ទំនិញប្រភេទកាហ្វេ (Coffee)** ប៉ុណ្ណោះ។ ហើយបង្ហាញតែសាខាដែលលក់បាន **លើស $4000**។

```sql
SELECT branch, SUM(amount) AS coffee_revenue
FROM Sales
WHERE product_type = 'Coffee'  -- ច្រោះយកតែកាហ្វេសិន មុននឹងបូក
GROUP BY branch
HAVING SUM(amount) > 4000;     -- ច្រោះយកលទ្ធផលក្រោយបូករួច
```

ក្បួននេះគឺអស្ចារ្យណាស់សម្រាប់ការវិភាគ! នៅក្នុងមេរៀនបន្ទាប់ យើងនឹងរៀនពីបច្ចេកទេសដ៏ស្មុគស្មាញបំផុតរបស់ SQL គឺការផ្សំតារាង ២ បញ្ចូលគ្នា (JOINs)។
